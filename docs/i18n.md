# Texts and translations

Arcalo shows every text in German and English. This page sets the rules for both languages and
explains the automatic check that enforces them.

## Where texts live

- **Interface:** `ui/src/locales/en.ts` (English, the source of the key type) and
  `ui/src/locales/de.ts`. Keys are grouped by area (`area.name`). Components call `t("area.name",
  { name })`; texts written into the code fail `ui/src/lib/i18n-strings.test.ts`.
- **Backend** (error messages, notifications, the tray and menus, generated pages, AI
  instructions): pairs in the Rust code, `tr!("Deutsch", "English")` for a fixed text and
  `trf!("„{name}“ fehlt", "“{name}” is missing", name = …)` for one with values
  (`crates/arcalo-core/src/i18n.rs`).
- **Release highlights:** `docs/releases/highlights/<version>.json`, an `en` and a `de` block per
  item.
- **Glossary:** `ui/src/locales/glossary.json`, the preferred term per concept and the variants
  that must not appear.

## Adding a text

1. Add the key to `en.ts` and `de.ts` at the same place (the typecheck fails if one is missing).
2. Use the same `{placeholders}` in both languages. A text with a count is a plural:
   `{ one: "{n} Seite", other: "{n} Seiten" }` – the form is picked by `n` (or `count`). Do not
   write `Seite(n)` or `page(s)`.
3. Name things with the glossary terms and keep the address form (below).
4. Run `npm --prefix ui test`. The translation check names each problem with its key.
5. In Rust, write `tr!` / `trf!` with literal strings; the check reads them from the source.

## Address form

German texts say **du** (as the onboarding, settings and hints do), or stay impersonal:
„Ordner wählen“, „Einstellungen öffnen“, „Zum Sortieren klicken“. Never „Sie“, „Ihr“, „Ihnen“ for
the reader. A „Sie“ that means „they“ (`Sie werden gelöscht.`) is fine. AI instructions address
the model with „du“ too.

English texts are plain and direct: „Choose a folder“, „You can change it later“.

## German typography

- Quotes „…“ (opening low, closing high). Straight quotes only in code and syntax
  (`/zeit … "Beschreibung"`, JQL); English quotes “…” only in English texts.
- The ellipsis character „…“, never three dots. Menu items that open a dialog end in „…“. A
  label, button, placeholder or progress text ends in „…“ right after the word („Board
  exportieren…“, „Wird synchronisiert…“); a space only where words are left out inside a sentence
  („Was habe ich am … gemacht?“).
- The en dash with spaces „ – “ between words and for ranges „8–18 Uhr“, never a hyphen with
  spaces.
- One space between words; no space before , ; : ! ? .
- A space between number and unit: „10 Min.“, „2 Std.“, „80 %“, „5 MB“. Abbreviations with a
  dot: „z. B.“, „Min.“, „Std.“, „Nr.“.
- Dates as 02.10.2026 (`TT.MM.JJJJ`), times as 14:30 or „14 Uhr“. ISO dates only in syntax
  (`due:2026-10-02`).
- Compounds are written together or with a hyphen, never apart: „Zeiterfassung“,
  „Lesezeichendatei“, „Markdown-Kopie“, „Jira-Issue“.
- After a colon a full sentence starts with a capital letter: „Aus: Die Antwort erscheint erst …“.
- Umlauts and ß always, also in file names shown as text („Wiederherstellungsschlüssel“).

English texts use “…” quotes, the same dash and ellipsis, sentence case for labels and „e-mail“.
English weekdays are abbreviated as „Mon, Tue, Wed“ (German „Mo, Di, Mi“).

## Keys, hours, dates and error titles

- **Keys** are named as the keyboard of the language prints them: German „Strg“, „Umschalt“,
  „Eingabe“, „Entf“, „Leertaste“; English "Ctrl", "Shift", "Enter", "Delete", "Space". Shortcuts
  in tooltips and menus come from `lib/shortcut.ts` (`keys`, `formatShortcut`, `keyName`), which
  takes the names from the catalog (`keys.*`); texts with a shortcut get it as a `{keys}`
  placeholder instead of writing it out.
- **Hours** are shown one way, as set under „Stunden als“: `fmtDuration` / `fmtMinutes` /
  `fmtHours` in `lib/format.ts` („1,50 h“ or „1:30 h“). No view formats hours on its own.
- **Week headings** use `weekRange` („5.–11. Oktober 2026“).
- **Error titles** (keys ending in `Failed`) name what failed: „Seite nicht gespeichert“ /
  "Page not saved", or the action: „Speichern fehlgeschlagen“ / "Saving failed". Never „Nicht
  gespeichert“, „Konnte nicht …“, "Could not …" or a bare „Fehler“; the cause goes in the detail.
- **Counts** use a plural for every count placeholder (`{n}`, `{count}`, `{total}`, `{pages}`, …),
  not only for `{n}`.

## The automatic check

`ui/src/lib/translations.test.ts` runs with `npm --prefix ui test` (and so in CI). It reads both
catalogs, every `tr!` / `trf!` pair under `crates/` and `src-tauri/src/` and the release
highlights, and fails on:

| Rule | What it finds |
|---|---|
| keys | a key missing in one catalog, an empty text, a plural in only one language |
| placeholders | different `{placeholders}` in German and English (per plural form), `(s)`/`(e)` plural hacks, „{n} things“ without a plural |
| format-args | different `format!` arguments in the German and English text of a `trf!` |
| quotes | straight or English quotes in German, unbalanced „…“, German quotes in English |
| typography | `...`, a space before a final „…“, double spaces, a space before punctuation, „ - “ instead of „ – “, units without a dot or space, US or ISO dates in German prose |
| error-title | a `…Failed` text that starts with „Nicht“, „Konnte nicht“, "Not", "Could not" or is a bare „Fehler“ / "Error" |
| address | „Sie“, „Ihr …“, „Ihnen“ addressing the reader, „Geben Sie …“ |
| glossary | a forbidden variant from `glossary.json` |
| take-over | "take … over" in English, also split around its object ("Take all over", "takes them over"): „übernehmen“ is import, apply or keep |
| leftovers | English UI words in German texts, umlauts and German words in English texts |
| spelling | ae/oe/ue/ss instead of ä/ö/ü/ß, doubled words, „die seite“ (lower-case noun after an article) |

Code spans, `[[links]]`, URLs and placeholders are left out before the rules look at a text.
German labels of buttons and menus more than twice as long as the English one (and over 30
characters) are printed as a warning only.

A true exception goes into `ALLOWED` at the top of the test, with the rule, the key (or Rust
file), a part of the text and the reason. Unused exceptions fail the check, so the list stays
short. The test also checks itself: every rule has an example it must find and examples of
correct German it must leave alone.
