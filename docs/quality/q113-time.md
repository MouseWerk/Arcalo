## Design decisions
- Source view: removals are found when the view saves (debounced 700 ms, on blur, on close), from the diff of chip ids between the text compared last and the text being saved; only chips the link check knows as booked on this page count (as in the rich editor: unknown or another note's chips never delete). Text of another pane (merged or taken over) is moved into the compared text, so a removal another editor made is acted on there only. A quick typo inside the tag that is fixed before the save does nothing; a broken tag that is saved counts as removed, and fixing it within the toast keeps the booking.
- „Rückgängig“ in the source view inserts the chip's exact Markdown where it was (mapped through later edits, as the caret is). The text box's own undo brings the text back, and the save then restores the booking (same id when free; otherwise the chip's `id` is rewritten).
- The removal machinery (`chipRemoved`, `chipReturned`, `chipsPresent`, `chipAwaited`) is shared by both editors; the open-editor registry counts source views, so a chip cut in one and pasted into the other (either kind) keeps its booking, and the target note's link check moves the booking to it.
- Kept link (`time_entry_issues_deleted`): written in `jira::delete_entry` for every deletion (chip removed or timesheet), dropped after 30 days or when taken back. Taking it back: link `pending` with the old worklog id (updated in place, or posted anew on 404 and the new id stored); a link that was never posted keeps its state and attempts (`posting`/`failed` retries look for a worklog an interrupted try left). Only the same booking (Netzplan and Vorgang) takes a link back.
- e2e holds a deletion with the fake Jira stopped (connection refused); `state.fail` is not used there, as other requests of the note (issue chips) can consume it.

## Left open
- WebDriver keys do not reach WebKitGTK's editing commands, so e2e uses `document.execCommand("undo")` for the text box's undo (what Ctrl+Z does there); the test shows the undo stack survives the view's saves.
- After a restart the in-memory snapshot of a booking deleted with its chip is gone: Ctrl+Z then brings back the chip text without booking (it shows as not booked and offers „Erneut buchen“, which takes the kept Jira link back).
