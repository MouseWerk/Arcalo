# Arcalo 1.12 quality pass, area A4: AI

Format: [severity] title — repro — root cause — fix — test

## Findings

1. [high] Stop does nothing while the model list or the search embedding is fetched
   - Repro: provider whose /v1/models answers slowly (company server under load); send a chat
     message; press Stop at once. The Stop button stays, the request runs on (and is billed)
     until the server answers; the inline AI bar / meeting summary keep "busy" too.
   - Root cause: the cancel flag of a request is registered only inside `stream_completion` /
     `wait_cancellable`; `ai_cancel` for an unknown id is a no-op. `ai_chat` (learn modes, query
     embedding up to 8 s) and `complete_routed` (`catalog()`, model lists up to 10 s) await
     before that, and between retries the flag is gone as well.
   - Fix: a `CancelScope` registers one flag per request id for the whole command (nested
     scopes share it); `complete_routed` returns the cancelled answer before sending when Stop
     came early.
   - Test: e2e 170 (slow model list, Stop ends at once, no chat request sent).

2. [medium] Inline AI bar, meeting summary and day review summary show raw server errors
   - Repro: wrong API key / server down, run "Kürzen" in the inline bar: "Anfrage fehlgeschlagen"
     plus a monospace blob (`KI-Server meldet Fehler 401: {...}`), no hint, no way to settings.
   - Root cause: only the assistant's `ErrorNote` used `aiErrorSummary`.
   - Fix: shared `AiErrorNote` (cause, how to fix, details, "Verbindung prüfen") used in all of them.
   - Test: e2e 170 (wrong key in the inline bar shows the denied hint and the settings button).

3. [medium] Inline AI bar and meeting summary without any AI: presets start a request that fails
   - Repro: fresh install (no provider key), select text, Ctrl+J, click "Kürzen" -> error blob.
     "Zusammenfassen" in a meeting note starts a request at once and fails.
   - Fix: both show a clean empty state ("Keine KI verbunden" + "KI einrichten" opening the AI
     settings) instead of dead/failing actions.
   - Test: e2e 170.

4. [low] Tag suggestions offer "Tags mit KI vorschlagen" with an enabled provider that has no key
   - Root cause: own check (`enabled`) instead of `usableProvider` (key present) used elsewhere.
   - Fix: use `usableProvider`.
   - Test: e2e 170.

5. [low] "Leere Antwort des KI-Servers (Grund: …)" is German in the English UI
   - Fix: tr!/trf! pair. Test: Rust unit test of `checked` in English.

6. [medium] Every AI request without a usable provider went to the default LiteLLM URL
   - Repro: fresh install, send a chat / run a briefing: "Verbindungsfehler ... localhost:4000 ...
     Connection refused" (or 401), the hint says to check the server.
   - Fix: `complete_routed` answers "Keine KI verbunden (Einstellungen → KI & Modelle)." at once;
     `aiErrorSummary` maps it to "Keine KI verbunden." with the setup hint and settings button.
   - Test: vitest aierror, e2e 170 (assistant without AI).

7. [low] "Verbindung prüfen" / "KI-Einstellungen" opened Settings on the last section viewed
   - Fix: `openAiSettings()` (openSettingsSection("ai")). Test: e2e 170.

8. [low] Provider row said "Keine Verbindung" for a rejected key (server reachable)
   - Fix: "Zugang abgelehnt – Schlüssel prüfen" when the test failed with 401/403. Test: e2e 170.

9. [low/visual] An empty chat taller than the panel was scrolled to its end (heading and setup
   note out of view at 1280x800 and narrower) — the resize observer stuck to the end without turns.
   - Fix: only follow the end once there are turns.

10. [low/visual] Settings → Sprachnotizen had no section title/intro (every other section has one).
    - Fix: SectionHead with intro.

11. [low/visual] Meeting summary dialog without AI left a 120 px empty preview area; fixed with
    `:has(> .ai-setup-note)`.
