Arcalo 1.20.0

## Improved

- Setting up Git sync takes four steps: choose the provider (GitHub, GitLab, Gitea/Forgejo, Bitbucket or another server), create a token with one button that opens the provider's page with the needed rights, pick a repository from the list or create a new private one, and check. The previous form stays under „Manuell einrichten“.
- The check before saving says in plain words what is wrong and how to fix it (token expired or without the right, no write right, repository not found, proxy or certificate, SSH address), and what the first sync does with content already in the repository. Nothing is overwritten.
- Pasted addresses are understood: repository pages from the browser, with or without .git; for an SSH address the HTTPS address is offered.
- Opening the Git setup again keeps syncing the branch your notes are on, and a second computer joins the notes on the same branch instead of starting another one.
- The setup asks for a new token when you switch to another server; the saved token is only ever sent to its own server.
- Bitbucket: the setup explains which access tokens work (repository, project or workspace access tokens) and does not offer to create a repository there.
- On touch screens and with a pen, a long press opens the context menu; dividers between panes have a wider grip, and buttons that appear on hover with a mouse are always visible without one.

## Fixed

- Bitbucket access tokens sign in to the Git sync correctly.
- „Testen“ in the manual Git form no longer sends the saved token to another server; the result says when it tested without it.
- A saved address with a user name and password no longer shows them in the setup.
- Replacing the token in the setup can no longer leave a new token next to the old address.
- A long press or a resting pen no longer opens a menu while drawing, on the canvas or while dragging; on Windows touch screens only one menu opens per press.

## Checklist for Windows (manual)

- Git sync setup with a real GitHub account: „Token erstellen“ opens the token page with „repo“ ticked and the description filled; paste the token, the list shows your repositories; create a new private repository; the check is green and the first sync runs. Open the setup again and save: the sync keeps its branch.
- The same with a GitLab account (token page with name and rights preselected; creating a project needs the „api“ right) and, if at hand, Gitea/Codeberg and a Bitbucket repository access token.
- With a GitHub token saved, open the setup and choose GitLab: the setup asks for a new token.
- On a touch screen or with a pen: press and hold a page in the sidebar opens one menu; drawing with a pen in a drawing and on the canvas opens no menu; drag a pane divider with a finger.
